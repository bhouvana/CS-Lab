# Regression Registry

Every real bug this project has found -- through testing, benchmarking, or
this hardening pass -- with where the fix lives and where the test is that
keeps it fixed. If any row's test is deleted or weakened, the bug it names
can come back silently.

| # | Bug | Fix | Regression test |
|---|-----|-----|------------------|
| 1 | **FNV-1a weak avalanche** inflated bloom-filter's measured false-positive rate above the theoretical prediction. | [`algorithms/bloom-filter/src/lib.rs`](../algorithms/bloom-filter/src/lib.rs) -- FNV-1a run twice with different offset bases, combined via an xor-shift-multiply mixing step. | [`algorithms/bloom-filter/tests/tests.rs`](../algorithms/bloom-filter/tests/tests.rs): `false_positive_rate_matches_theory_within_tolerance_regression` |
| 2 | **`%zu` printf quirk on MinGW.** MinGW's default (non-ISO) `printf`/`scanf` don't recognize `%zu`/`%lld`. | [`compilers/bytecode-vm/include/vm.h`](../compilers/bytecode-vm/include/vm.h): `#define __USE_MINGW_ANSI_STDIO 1` under `#ifdef __MINGW32__`. | Exercised by every `%zu`-printing test in `compilers/bytecode-vm/tests/test_vm.c` on a native Windows/MinGW build; no crash/garbled-output means the macro is doing its job. |
| 3 | **`clock()` resolution too coarse** (~15ms on Windows) to time a single small operation -- read as 0ms or produced meaningless ratios. | Repeat the operation until `MIN_MS` has elapsed, report the per-run average. Applied in `crypto/sha256/src/bench.c`, `compilers/bytecode-vm/src/bench.c`, `runtimes/garbage-collector/src/bench.c`, and (this pass) `compression/huffman/src/bench.c`. | No automated test (it's a benchmark quality issue, not a correctness one) -- verified by hand each time: reproduced the 0.000ms reading on native Windows/MinGW, confirmed non-zero readings after the fix. See `docs/engineering-audit.md` finding #3 for this pass's instance. |
| 4 | **Recursive GC marking could stack-overflow** on a deep reference chain. | [`runtimes/garbage-collector/src/gc.c`](../runtimes/garbage-collector/src/gc.c): iterative DFS via an explicit heap-allocated worklist, not recursion. | [`runtimes/garbage-collector/tests/test_gc.c`](../runtimes/garbage-collector/tests/test_gc.c): `a 200000-deep reference chain marks without a stack overflow` |
| 5 | **Allocator "leftover tail" masked fragmentation** in a benchmark -- an unallocated remainder block made fragmentation look better than it was. | [`os/allocator/src/bench.c`](../os/allocator/src/bench.c): benchmark setup accounts for the leftover block explicitly instead of ignoring it. | [`os/allocator/tests/test_allocator.c`](../os/allocator/tests/test_allocator.c): asserts the expected block count including "one alloc + one leftover free block". |
| 6 | **TCP chat shared-server test isolation race** -- tests sharing one server process could observe each other's messages. | [`networking/tcp-chat/tests/test_chat.c`](../networking/tcp-chat/tests/test_chat.c): each test forks its own server on its own port. | `ok: a newly joined client sees no earlier private exchange` in the same file. |
| 7 | **`SIGPIPE`'s default action silently killed the chat server** the moment two clients disconnected at the same time (a write to an already-closed socket raises `SIGPIPE`; unhandled, its default action terminates the process). | [`networking/tcp-chat/src/server.c`](../networking/tcp-chat/src/server.c): `signal(SIGPIPE, SIG_IGN)`. | `ok: simultaneous disconnects don't crash the server (SIGPIPE regression)` in `test_chat.c`. Confirmed by disabling the fix and watching this test catch it before re-enabling it. |
| 8 | **Bytecode VM silently skipped unrecognized opcodes** instead of rejecting them -- `vm_run()`'s dispatch `switch` had no `default` case, so an out-of-range `Opcode` value just fell through and execution continued. Found during this hardening pass while adding sanitizer coverage. | [`compilers/bytecode-vm/src/vm.c`](../compilers/bytecode-vm/src/vm.c): added a `default` case that reports and rejects it, same as every other invalid-input path. | [`compilers/bytecode-vm/tests/test_vm.c`](../compilers/bytecode-vm/tests/test_vm.c): `test_invalid_opcode_invalid_case`, plus a 20000-program deterministic fuzz test (`test_random_programs_never_crash_fuzz`) that exercises the same path at volume. |

Bugs #1-#7 predate this hardening pass (found during the original 20-lab
build). Bug #8 was found during it, while wiring up ASan/UBSan coverage --
see `docs/engineering-audit.md` for the rest of what this pass touched.
